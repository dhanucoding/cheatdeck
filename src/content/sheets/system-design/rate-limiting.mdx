## TL;DR
Cap how many requests a client can make in a time window. Reject extras with **HTTP 429** and a `Retry-After` header.

## Algorithms
| Algorithm | Allows bursts | Memory | Notes |
|---|---|---|---|
| Token bucket | Yes (up to capacity) | O(1) per key | Most common default |
| Leaky bucket | No (smooths output) | O(1) | Good for steady downstream rate |
| Fixed window | Edge spikes (2x) | O(1) | Simple but leaky at boundaries |
| Sliding window log | No | O(n) | Exact, expensive |
| Sliding window counter | Approx. | O(1) | Good accuracy/cost balance |

## Where to enforce
- **API gateway / edge**: cheapest, protects everything behind it.
- **Per service**: needed for fairness between internal callers.
- **Shared state** (Redis `INCR` + `EXPIRE`, or a Lua script) when you run many instances.

```python
# Token bucket, single process
import time

class Bucket:
    def __init__(self, capacity, rate):
        self.cap, self.rate = capacity, rate
        self.tokens, self.ts = capacity, time.monotonic()

    def allow(self):
        now = time.monotonic()
        self.tokens = min(self.cap, self.tokens + (now - self.ts) * self.rate)
        self.ts = now
        if self.tokens >= 1:
            self.tokens -= 1
            return True
        return False
```
